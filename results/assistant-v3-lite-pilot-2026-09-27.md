# Assistant V3 × SREGym-Lite pilot — 2026-09-27

Browse the [one-folder-per-case dossiers](by-case/README.md) for exact starter prompts, benchmark oracle source, Splunk-visible evidence and limits, final answers, raw traces, judge output, and execution metrics. These are verified standalone copies of the selected valid attempts.

Earlier pre-agent and infrastructure-invalid attempts were excluded, including DNS, Valkey, Kafka, readiness-probe, duplicate-PVC, and search-retry retries. They informed checker and trace-path fixes, but no failed attempt or provisional score was substituted for the 21 valid results below. The active result set now contains only one valid dossier per case; the older numbered-run folders were moved to macOS Trash for recovery until it is emptied.

Completed first-pass, local-only 21-case pilot: mean benchmark score **38.9/100**, median **34**, with five scores at least 70 and four zeroes. All scored rows used the synthetic Splunk org, SREGym `svelte` deployment, the symptom-guided time-window prompt, Assistant V3 with `gpt-5.6-luna`, and the unchanged SREGym Azure `gpt-5.6-luna` diagnosis judge. These runs are **not leaderboard-comparable**. The benchmark score is not a Splunk-visible score or a determination that the complete fault mechanism was named.

Each linked per-case dossier contains the exact saved starter prompt, raw final answer, original judge CSV and critique, native events, ATIF trajectory, phase ledger, terminal submission status, runtime/token/tool metrics, source-vs-Splunk pre-agent causal check, and post-run representative delivery proof. Collector closing audits were valid for every scored row. A six-class delivery check is representative, not exhaustive source/destination parity.

The NetworkPolicy and readiness-probe results illustrate a rubric caveat: each received 1.00 for fault localization, 0.33 for fault characterization, and 1.00 for scope precision, producing a rounded 0.78 composite above the rubric's 0.70 pass threshold. Both answers explicitly said the underlying mechanism was unknown; neither named the injected NetworkPolicy or the bad readiness probe. Treat these as successful localization but **not** full RCA resolution. The NetworkPolicy answer also cited unrelated shared-org environments, so its entity/time scoping needs separate review.
